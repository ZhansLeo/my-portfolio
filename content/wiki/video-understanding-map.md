## 1. 研究地图：从能力到系统

### 1.1 视频理解需要哪些能力

看见门，不等于知道已经经过这扇门；识别杯子，不等于知道谁把杯子放在桌上；描述整个视频，也不等于定位支持某个判断的片段。

| 能力 | 要回答的问题 | 可能暴露的问题 |
|---|---|---|
| 外观感知 | 画面中有什么？ | 小物体、遮挡、相似目标混淆 |
| 运动与时间关系 | 什么发生了，先后如何？ | 把出现顺序当作事件顺序 |
| 长程联系 | 现在的对象与先前有什么关系？ | 身份混淆、历史遗忘 |
| 证据定位 | 哪一段支持这个结论？ | 答案合理却缺少依据 |
| 主动取证 | 还需要看哪一段？ | 反复检索但没有增加有效证据 |
| 在线响应 | 当前信息是否足够行动或回答？ | 使用未来信息，或响应太晚 |

这张表是本文用于学习的分析框架，不是所有模型共享的内部模块划分。

### 1.2 表示、语言模型与交互系统

**视频表示层：**把像素序列转换成可被下游使用的特征。关注模型保留了什么，以及用什么训练目标学习。

**多模态语言模型层：**将视觉表示接入语言模型，通过对齐与指令训练支持描述、问答等输出。

**交互系统层：**组织历史、检索工具、状态与多次模型调用。性能提升可能来自工具与上下文组织，不一定来自编码器变化。

同一工作可能跨层。评测时应分别记录模型、数据、输入预算、工具权限和运行成本，避免只比较最终准确率。

## 2. 从视频表示到多模态对话

理解导航中的视频能力，先要弄清像素怎样进入模型、训练如何使这些表示可被语言使用。InternVideo 与 VideoChat 可以分别提供表示和对话接口的入口；它们不是简单的前后替代关系。

### 2.1 先用一条数据流理解系统

视频经过抽帧或切片，由视觉编码器得到特征；接口把视觉信息变成语言模型可处理的表示；模型结合问题生成答案。不同系统可以在抽帧、编码、压缩、对齐、训练与交互阶段做改变。

| 环节 | 阅读代码时找什么 | 容易误解的地方 |
|---|---|---|
| 视频读取 | 帧率、时间戳、采样位置 | 原视频很长，不代表全部进入模型 |
| 编码 | 输入形状、时间维度如何处理 | 多张图像不自动等于充分理解运动 |
| 接口 | 特征投影、查询或压缩 | 接上语言模型不等于完成视觉对齐 |
| 生成 | 问题、提示、输出形式 | 流畅答案可能依赖语言常识 |

### 2.2 InternVideo：先研究视频特征

**问题与方法入口。**初代 InternVideo 将生成式与判别式学习用于通用视频表示，理解重点是不同训练目标对特征施加了什么约束，而不是先记住排行榜。[论文](https://arxiv.org/abs/2212.03191)

**读图任务。**给架构图中的每个损失函数写一句话：模型必须保留什么才能完成这个目标？再检查相应下游实验是否真的支持这项能力。

**待核对。**相同编码器在动作识别、检索和问答中扮演的角色是否相同？具体使用哪套权重、何种采样策略？

### 2.3 InternVideo2：把训练过程分成能力建立的阶段

InternVideo2 采用渐进式训练，把掩码视频建模、跨模态对比学习和下一 token 预测组织起来。学习时可以分别理解为视觉表示、跨模态对应与生成输出，但这种解释不能替代论文的具体训练设置。[论文](https://arxiv.org/abs/2403.15377)

| 阅读问题 | 应寻找的证据 |
|---|---|
| 为什么需要分阶段？ | 去掉或改变阶段的消融 |
| 数据与模型规模各贡献什么？ | 尽可能匹配其余条件的对照 |
| 特征更好是否必然提高时序推理？ | 依赖先后关系而非单帧外观的任务 |

**个人理解。**不要把“编码器变大”“语言模型更强”“训练数据更丰富”合并为一个原因。阅读记录至少保留输入、训练目标和评测三列。

### 2.4 VideoChat：让表示支持对话

VideoChat 用可学习接口连接视频基础模型与语言模型，并构造视频指令数据。它提供理解视频对话系统的早期入口：视觉信息如何进入语言上下文，训练如何让模型围绕视频作答。[论文](https://arxiv.org/abs/2305.06355)

**边界。**一段正确的事件描述，不能单独证明模型已掌握因果推理。应区分作者的能力主张、定性例子和可重复的定量证据。

**阅读练习。**选择一个顺序敏感的问题，标出答案需要哪些帧。若只看一张关键帧就能回答，它不适合检验真正的长程时间理解。

### 2.5 VideoChat3：从单个接口走向综合能力

VideoChat3 的公开摘要强调通用、长视频与流式场景的数据构建和高效理解。它适合用于追踪能力来自哪里：架构、训练数据、上下文组织或任务监督。[论文](https://arxiv.org/abs/2607.14935)

**精读清单。**分别记录三类场景的输入权限、监督形式与测试方式；比较时避免把离线问答成绩解释为在线交互能力。当前不将数据规模直接转写为性能原因，需进一步核对消融。

### 2.6 InternVideo-Next：从文本标签以外学习世界信息

其预印本讨论不依赖视频文本监督的视频表示学习，动机包括文本描述可能遗漏运动、几何与物理线索。[论文入口](https://arxiv.org/abs/2512.01342)

**概念边界。**编码器能提取世界相关信息，不代表它已学习“执行某个动作后会发生什么”的动力学模型。与 DINO-WM、NWM 的比较应先对齐生成对象、动作条件和训练目标，再判断联系。

### 2.7 第一项可做的练习

在作者仓库中定位视频加载、视觉编码和模型推理三个入口，先画调用图。需要推理资源后，只运行一个固定视频与一个问题，保存采样时间戳、模型版本、提示和输出。此时称为“跑通推理”，不称为完整复现。

代码入口：[InternVideo 官方仓库](https://github.com/OpenGVLab/InternVideo)。不同模型依赖和显存要求分别检查，不默认本机集成显卡能运行 CUDA 配置。


## 3. 长视频：在信息预算内保留关键内容

能够对短片作答以后，难点转向更长的时间范围：有限输入怎样同时覆盖全程并保留局部细节？这一章承接表示问题，讨论信息在哪一步被选择、压缩或丢失。

### 3.1 长视频的困难不是只有长度

假设一个关键事件只持续一秒。均匀稀疏抽帧可能完全错过它；提高采样密度增加计算成本；保留更多帧后再压缩，也可能删掉区分事件的细节。

需要同时考虑时间覆盖、图像细节、上下文预算与查询相关性。更多输入不自动代表更多有效证据。

### 3.2 InternVideo2.5：长而丰富的上下文

InternVideo2.5 关注细粒度视觉信息与长程时间结构，提出 Long and Rich Context 建模。阅读应检查哪些设计使细节与长时间覆盖能够同时保留，而不只摘录可处理的视频长度。[论文](https://arxiv.org/abs/2501.12386)

**需要核对的证据。**相同输入预算下的比较、不同长度的性能变化，以及细节任务与长程任务是否同时受益。作者报告的提升只对应其设置，不直接代表任意视频或导航轨迹中的可靠记忆。

### 3.3 VideoChat-Flash：压缩在哪里发生

VideoChat-Flash 研究分层压缩，并结合从短到长的训练与长视频数据。其入口包括上下文容量及稀疏证据测试。[论文](https://arxiv.org/abs/2501.00574)

**精读时画三条线。**第一条是原始视频时间线，第二条是被采样的帧，第三条是压缩后保留的表示。这样才能区分“没采到”与“采到了但表示丢失”。

**边界。**在长视频中找到一个特殊片段，与理解多个相似事件的关系，不是同一个难度。容量测试需要与事件关系测试一起看。

### 3.4 两篇放在一起时比较什么

| 维度 | 应记录什么 | 为什么重要 |
|---|---|---|
| 输入 | 帧数、分辨率、视频长度 | 防止多给输入造成不公平比较 |
| 压缩 | 所在层、预算、查询是否已知 | 决定能够保留什么 |
| 训练 | 主干、数据、训练阶段 | 防止把全部收益归于压缩 |
| 输出 | 描述、问答、定位等 | 不同任务不能直接混用指标 |
| 成本 | 显存、延迟、总 token | 衡量能力与效率的取舍 |

目前这是一张比较模板，数值应在读完具体实验后填入，不预填未经核对的排行榜结论。

### 3.5 一个最小诊断实验

固定模型、问题和解码设置，选择具有明确关键事件的视频，比较均匀抽帧与相同帧数的人工关键帧。记录答案是否变化，再检查模型究竟看到了哪些证据。

人工关键帧是诊断上限，不是可部署算法。离线看完整视频选片是允许的诊断设置；迁移到在线导航时必须只使用当前之前的片段。随机或均匀抽帧需保留种子或时间戳，不能只展示最好的一次。

**可解释的结果。**若关键帧改善回答，说明证据供应值得继续研究，但尚不能区分压缩、位置编码、提示变化等原因；若不改善，则需要继续检查感知与推理。

### 3.6 与导航历史的连接

机器人反复看见相似门口时，视觉冗余与事件冗余并不相同。相似画面可能表示回访同一个位置，也可能是经过新的位置。这是可供验证的问题，不是断言现有压缩方法必然失败。

参照 [VLN 知识库中的 StreamVLN](vln-learning-notes)，先核对它保留什么，再设计具有重复地标的案例，不凭“压缩了”推断“忘记了”。


## 4. 时间证据与主动推理

保留了足够长的上下文，还需要找出真正支持答案的部分。时间定位把证据变成可检查的对象，主动推理则进一步决定下一次应该查看哪里。

### 4.1 从答案追溯到证据

“他已经拿走钥匙”包含对象身份、事件发生及完成状态。单独问答案对不对还不够：应进一步标注哪个时间片段提供依据，其他片段是否存在冲突。

证据定位帮助检查判断，但模型提供的解释与时间戳仍可能错误，需要与实际画面对照。

### 4.2 TimeLens2：证据可以是多个片段

TimeLens2 将通用视频时间定位表述为区间集合预测：一个问题可能由多段时间证据支持。论文围绕多片段监督构建及区间集合的奖励展开。[论文](https://arxiv.org/abs/2607.17423)

**阅读重点。**为何单一连续区间不足？预测一个宽区间覆盖全部证据，与准确给出多个片段有什么区别？奖励如何处理不同数量和碎片化的区间？

**实践入口。**先人工标一条查询需要的证据集合，记录开始、结束和证据内容。再比较模型输出。不要把包含答案画面的任意大区间都视作精确定位。

### 4.3 Video-o3：让推理与查看视频交替进行

固定采样先决定模型能看到什么，再要求它完成推理。然而多跳问题中的后续线索，可能要在前一次判断之后才能确定。Video-o3 因此把寻找线索、细查片段和推理交错组织起来，并在证据充分时结束。

这改变了推理过程的信息流：模型不只利用给定画面回答，还要决定下一次查看的位置。论文提出任务解耦的注意力掩码、可验证轨迹引导奖励，以及 Seeker-173K 工具交互数据，分别围绕推理与工具调用的组织、探索和效率的训练展开。具体计算仍需结合正文精读，不能把这些名称本身当作机制解释。

评价时需要同时看最终结果与取证过程：去掉各设计后发生什么变化？其他方法是否有相同工具和观察预算？更多调用带来的是新证据，还是重复开销？这些对照才能说明主动查看的价值。

离线检索改变读取范围，机器人移动则改变实际观察和位置。因此，这项工作提供的是主动组织证据的参考，不能直接等同于导航策略。来源：[Video-o3 论文](https://arxiv.org/abs/2601.23224) · [官方实现](https://github.com/MCG-NJU/Video-o3)。

### 4.4 如何观察一次真实推理

| 步骤 | 记录内容 | 要检查的联系 |
|---|---|---|
| 初始输入 | 问题与最初提供的片段 | 是否已包含足够证据 |
| 请求观察 | 模型选择了哪个时间段 | 为什么该片段可能有用 |
| 返回结果 | 实际新增的画面或信息 | 是否与请求一致 |
| 判断更新 | 答案、假设或下一次调用变化 | 新证据是否真的改变判断 |
| 终止 | 停止条件与最后答案 | 证据是否完整，有无矛盾 |

有些模型不输出可读推理，此时只记录可观察的工具调用和答案，不替它编造内部想法。公开视频若缺少中间观察，也应把相应字段记为未知。

### 4.5 与 SeekVLN 的联系及差别

二者都启发我们关注证据不足，但取证接口不同：回看视频改变的是读取范围，机器人转头或移动改变的是实际观察。后者还涉及运动代价、位置变化和闭环风险。

一个可验证的迁移问题是：导航进度判断出错时，缺少的是历史证据，还是当前环境中尚未看到的信息？先区分这两类，再决定检索历史还是主动观察。相关导航笔记见 [VLN 知识库](vln-learning-notes)。

### 4.6 当前学习产物

第一轮不要求实现新的取证算法。完成一条包含原始问题、观察时间段、工具调用和最终答案的记录即可。后续再比较固定观察预算下的不同取证方式，报告成本与失败，不只保留成功轨迹。


## 5. 在线理解、具身连接与实践

前面多数分析允许访问一段已录制视频；观察持续到来时，系统无法预知未来问题，也不能回看尚未发生的片段。在线记忆由此成为连接视频理解与闭环导航的关键一环。

### 5.1 视频没有结束时，问题发生了什么变化

离线视频可以定位并重读未来片段；在线系统只能利用已经发生的观察。问题可能晚于证据出现，系统必须在不知道未来查询的情况下决定记录什么。

真实导航还多出一层：行动改变未来观察，决策错误会把智能体带到不同位置。离线问答变好不能直接证明闭环导航更好。

### 5.2 OneStreamer：把记录与响应一起考虑

OneStreamer 研究查询无关的证据记录和任务响应，使用主动分层文字记忆，记录带时间信息的局部细节与已完成事件。[论文](https://arxiv.org/abs/2610.01762)

**精读重点。**当前观察、最近视觉上下文和文字历史分别怎么进入模型？何时形成事件记录？训练目标怎样避免依赖未来？

**待验证边界。**文字记录可能更紧凑，也可能丢失视觉细节或累积误记。能否更正历史、是否保留原始证据，要检查具体机制，不能仅凭“有记忆”推断可靠性。

### 5.3 视频能力到导航能力的映射

| 视频问题 | 导航对应问题 | 额外要求 |
|---|---|---|
| 长历史压缩 | 经过了哪些地标 | 区分回访与新事件 |
| 时间证据定位 | 子目标是否完成 | 只使用决策时已有观察 |
| 线索寻找 | 回看或转头取证 | 计入动作与时间成本 |
| 在线事件记录 | 持续跟踪任务进度 | 错误记录要能被新证据纠正 |

这是本文提出的理解映射，不代表现有模型已经适配导航。真正迁移时需重新对齐输入、输出、监督和闭环评测。

### 5.4 保留个人问题，而不急着宣称创新

我在导航演示中观察到走走停停，得到持续子目标的设想：局部目标明确时持续执行，必要时重新判断。后来发现 DualVLN 与总体路线接近。这段过程见 [VLN 知识库](vln-learning-notes)。

视频方向可能提供监测与证据组织的工具，但不能直接得出“加上视频模型就能改进导航”。目前更有用的问题是：错误首次发生时，证据是否出现、是否保留、是否被正确解释？

| 候选问题 | 最小检查 | 什么结果会削弱假设 |
|---|---|---|
| 历史压缩丢了关键事件 | 等预算关键帧与均匀帧比较 | 提供关键帧仍不能改善判断 |
| 当前判断缺少时间证据 | 要求定位依据并人工核对 | 依据准确但动作仍错，应转查执行 |
| 事件记录影响后续进度 | 对照原记录与人工纠正记录 | 纠正后仍无变化，或提示本身造成混杂 |

人工干预是诊断工具，不是部署能力。每个问题都还需要相关工作比较与实际样本，不能据此认定研究空白。

### 5.5 科研入门的三个实践台阶

**第一步：不运行模型也能做。**选一个有使用权限的短视频，列出帧时间戳、一个顺序敏感问题和人工证据。阅读数据加载器，明确模型会看到什么。

**第二步：获得推理资源后。**按作者检查点跑通一个例子，保留版本、配置、提示、输入与输出。固定其余条件，改变一项采样或上下文设置。这是推理检查，不是训练复现。

**第三步：接入导航环境。**加载场景和 episode，让动作改变环境，保存第一视角、目标、动作与时间。不要把固定视频上的回答当作闭环执行结果。

本机适合代码阅读、视频查看和日志分析；是否能运行模型依据具体设备、依赖和显存测试决定。服务器上已有环境通常更适合作为第一次推理入口，先问清环境、数据、权重位置和使用规则。

## 6. 怎样继续阅读与维护

面对失败，先问信息是否被观察到、是否被保留、能否被定位与解释，以及解释是否改善了任务结果。错过门口可能是没有拍到、压缩丢失、计数错误或执行失败，仅用“记忆不足”无法完成诊断。

下一轮先补齐表示与对话接口，再围绕 Video-o3 整理一次可核查的取证过程。有了固定视频与问题，再决定补读长视频或流式记忆。目标是一条完整的输入与输出记录，而不是不断扩大的阅读清单。

精读后补充架构与消融，推理跑通后记录配置与失败，确认训练和评测过程后再标记复现。个人想法写成可以被否定的问题，保留什么结果会削弱假设。
